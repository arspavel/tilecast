# LSR signage без доступа к интернету

Комплект для установки LSR signage на сервер в корпоративной сети, у которой нет
выхода в интернет. Всё нужное уже внутри: образы Docker, файл compose, скрипты
установки и резервного копирования, плееры для экранов.

## Что нужно на сервере

- Linux x86_64 (Ubuntu, Debian, Astra, РЕД ОС, CentOS и т. п.).
- Docker Engine 24+ и плагин `docker compose`. Если на сервере их нет,
  установите пакеты из внутреннего репозитория или скачайте `.deb`/`.rpm`
  заранее на машине с интернетом.
- 2 ядра, 4 ГБ памяти, место на диске под медиатеку (от 20 ГБ).
- Открытый порт 8080 (или другой, указанный в `.env`) для экранов и браузеров.
- Правильное время на сервере и экранах (корпоративный NTP): расписания
  и подписи работают по часам.

## Установка

1. Скопируйте `tilecast-offline-<версия>.tar.gz` на сервер.
2. Распакуйте и запустите установку:

   ```bash
   tar -xzf tilecast-offline-<версия>.tar.gz
   cd tilecast-offline-<версия>
   sudo ./install.sh
   ```

3. Скрипт проверит целостность файлов, загрузит образы, создаст `.env`
   со случайным паролем базы и запустит LSR signage. В конце он покажет адрес
   Studio, например `http://10.0.5.20:8080`.
4. Откройте этот адрес в браузере, создайте организацию и учётную запись
   владельца.

Проверьте `TILECAST_PUBLIC_URL` в `.env`. Экраны подключаются именно по этому
адресу. Если сервер доступен по DNS-имени или через обратный прокси с
корпоративным сертификатом, укажите это имя и снова запустите
`sudo ./install.sh`.

Храните папку комплекта: в ней лежат `.env` и резервные копии.

## Подключение экранов

В папке `players` лежат плееры из последних релизов на момент сборки комплекта.

**Android TV и Android-приставки** — `players/android/tilecast-player.apk`.
Установите APK (с USB-флешки или через `adb install`), запустите и введите
адрес сервера из `TILECAST_PUBLIC_URL`. Код привязки подтвердите в Studio.
Поиск сервера в сети (mDNS) в Docker не работает, адрес вводится вручную.

**LG webOS Signage** — проще всего без установки: на панели откройте
«Настройка Ez → Play via URL» и укажите `<TILECAST_PUBLIC_URL>/webos/`.
Такой плеер обновляется вместе с сервером. Второй вариант — установить
`players/webos/*.ipk` через SI Server или USB.

**Windows** — `players/windows/*.exe`, если файл есть в комплекте.

## Обновление плееров без интернета

Сервер работает в автономном режиме (`TILECAST_OFFLINE=true`) и не обращается
к GitHub. Обновления Android-плеера загружаются вручную:

1. В Studio откройте настройки обновлений плеера и загрузите три файла из
   `players/android`: `tilecast-player.apk`, `tilecast-player-update.json`,
   `tilecast-player-update.json.sig`.
2. Разверните релиз на экраны или группы.

Для своих сборок APK подпишите манифест скриптом
`scripts/sign-player-apk.sh` из репозитория.

На Android 11 и старше система попросит подтвердить установку на экране.
Без подтверждения обновление ставится на Android 12+ или когда плеер назначен
владельцем устройства (см. раздел про Managed Kiosk в документации).

## Обновление сервера

Соберите новый комплект на машине с интернетом
(`scripts/build-offline-bundle.sh`), перенесите на сервер, распакуйте рядом и
запустите `sudo ./install.sh` из новой папки, предварительно скопировав в неё
`.env` из старой. Скрипт сделает резервную копию базы, загрузит новые образы
и перезапустит сервер. Миграции базы применяются автоматически.

## Резервное копирование

```bash
sudo ./backup.sh            # база и медиафайлы
sudo ./backup.sh --db-only  # только база
```

Копии складываются в `backups/<дата-время>/`. Переносите их на другой носитель:
копия на том же диске не спасёт при отказе диска.

Восстановление (текущие данные будут заменены):

```bash
sudo ./restore.sh backups/20261026-120000
```

## Что не работает без интернета

- Виджеты и источники, которые берут данные из интернета: YouTube, погода,
  качество воздуха, внешние RSS и календари, сайты вне корпоративной сети.
- Проверка новых релизов на GitHub: плееры загружаются вручную, как описано выше.

Внутренние сайты и источники данных работают: в `.env` для них уже разрешены
частные адреса (`TILECAST_WEBSITE_ALLOW_PRIVATE_HTTP`,
`TILECAST_SOURCE_ALLOW_PRIVATE_NETWORKS`).

## Полезные команды

```bash
docker compose ps                    # состояние контейнеров
docker compose logs -f server        # журнал сервера
docker compose restart server        # перезапуск
docker compose down                  # остановка (данные сохраняются)
```
